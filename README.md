現在は C# / .NET 10 の接続確認用試作です。標準入力で GTP 2 のコマンドを受け取り、標準出力で応答します。KifuwarabeGo2026 v4.0.9 でのプレイヤー選択・着手は利用者が動作確認済みです。

## 起動

```powershell
dotnet run --project .\KifuwarabeGoPolypropylene.ThinkEngine
```

起動後、例えば次を1行ずつ入力します。

```text
protocol_version
boardsize 9
komi 6.5
play b D4
genmove w
showboard
quit
```

`genmove w` は `= A1` と空行を返し、白石を実際に置きます。応答の `=` は成功、`?` はエラーです。コマンド番号と `#` コメントも扱えます。通常運転中の標準出力は GTP 応答専用です。

## 動作テスト

外部テストパッケージを追加せず、次のコマンドで石の取り・自殺手・単純コウ・パス・座標・GTP 応答を検査します。失敗時は終了コードが非ゼロになります。

```powershell
dotnet run --project .\KifuwarabeGoPolypropylene.ThinkEngine -- --self-test
```

## 試作の範囲

- 2～19 路盤。黒・白の指定、パス、石の取り、自殺手禁止、単純コウ。
- 着手候補を A1 から順に仮想実行し、戦訓で失敗を回避します。全候補が除外された場合も合法手が残れば最初の合法手を打ち、合法手がなければパスします。
- 利用者指定の「純碁風の石数ルール」です。盤上の黒白の石数だけで判定し、同数は引き分け。空点・取った石・コミは加算しません。GTP の komi は接続互換のため受理しますが判定には使いません。
- 連続2パス、または黒白合計400手（パスを含む）で対局を終了し、GTP final_score で石数の勝敗を返します。400手目を受理した後は盤面を固定し、それ以上の play は拒否、genmove は盤面を変えず pass を返します。clear_board / boardsize で手数もリセットします。超コウ、時間管理、投了判断、置き石専用コマンド、undo、gRPC は未実装です。
- 対応コマンドは `list_commands` で確認できます。大会用としての完成品ではありません。

ソースは既存の ThinkEngine フォルダーに置いています。Board.cs は盤面と合法手判定、GtpEngine.cs は文字列の接続口、Program.cs は起動、SelfTest.cs は検証です。

## 戦訓と自動化サイクル（0.3.1）

最終対象は9路盤・19路盤、利用者指定の純碁風の石数ルールです（2026-11-23更新）。3路・5路は研究・回帰テスト用に使います。中国式の面積計算とは区別し、盤上の黒白石数だけを比較します。死石判定は行わず、盤上に存在する石をすべて数えます。中国式の面積計算ヘルパー Board.Score(double) は研究用に残していますが、対局結果・GTP final_score・定期検証の勝敗には使いません。

FolderVerse の `docs/dev/site-defense.md`、`FolderVerse/BattleLessons.cs`、`BattleLessons.Pursuit.cs` を参考に、失敗の観測と行動修正を分けています。FolderVerse の「目撃・帰還・研究」の演出は移植していません。

エンジン内では人の目視を待たず、候補手の仮想実行から次の失敗を自動検出します。

- `repeat-position`: 対局開始から記録した盤面へ戻る候補を回避する。パスは対象外。これは着手選択の方針で、外から受け取る着手の合法性判定は単純コウのままです。
- `fill-eye`: 上下左右が味方、斜めの敵石が内側なら1個以下・辺角なら0個の眼形を埋める候補を回避する。死活の完全証明ではなく局所的な判定です。
- `immediate-capture`: 取りを伴わない候補を仮に打ち、相手の合法な一手で置いた石が取られることを確認して回避する。捨て石の価値を読む機能はまだありません。
- `capture-reversal`: 石を取る候補でも相手の合法な直後の取り返しを調べ、取った敵石数より失う味方石数が多ければ回避する。同数以下、単純コウで禁止される取り返し、400手目後の応手は対象外。合法手しか残らないときのフォールバックは維持します。

初期状態では取得0件です。失敗を初めて観測した時点からその候補を避け、同じ盤面・直前盤面・色・候補の経験を再利用します。`kfw-lessons` は取得した種類と観測数・回避数をJSONで返します。報告は起動中の複数対局を通して保持し、局面履歴と経験キャッシュは `clear_board` / `boardsize` でリセットします。プロセス終了後の学習保存はありません。 ただし合法手が残る場合のフォールバックでは、戦訓が除外した候補を最終的に採用することがあります。回避数は候補を除外した試行回数です。

既知の4種類の検出と経験再利用がエンジン内の自動化です。未知の失敗から新しいC#の戦訓を作る部分は、定期タスクの Codex が対局証拠を読み、再現テストと実装を追加する開発サイクルとして行います。エンジン単体が未知のルールを発明する機能ではありません。
