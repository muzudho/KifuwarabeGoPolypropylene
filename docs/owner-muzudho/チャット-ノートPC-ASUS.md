そこで、交点の数は奇数にしたいんだぜ（＾～＾）  
* ２辺が偶数と偶数なら、面積は偶数。例： ８×８＝６４
* ２辺が偶数と奇数なら、面積は偶数。例： ８×９＝７２
* ２辺が奇数と奇数なら、面積は奇数。例： ９×９＝８１、１９×１９＝３６１
だから、ｎ路盤のｎは奇数にしたいんだぜ（＾～＾）

* １９路盤の面積は、１９×１９＝３６１

* ８１×２＝１６２
* １６９×２＝３３８

| 形 | 空けている眼 | 奇偶 |
|---|---|---|
| 左下 | A2・B1 | 奇数系 |
| 右下 | H2・J1 | 偶数系 |
| 左上 | A9・C9 | 偶数系 |
| 右上 | H8・J9 | 偶数系 |

どれも黒６石＋眼の空点２つ＝８交点だぜ。3×3の形は、外接する９交点のうち１点を使わずに済んでいるな。
エンジンでは「奇数点・偶数点への着手禁止」にせず、作ろうとしている二眼の空点を、自分で潰さないための局所的な形の目安として扱えるぜ。壁をつなぐためには、眼と同じ奇偶の点にも石が必要だからな。

なるほどだぜ（＾▽＾）完成形を知っていても、そこへ交互に石を置いて到達できるとは限らないんだな。

［ー＿ー］
なるほどだぜ（＾▽＾）「角」は隅の一点だけでなく、その隅を足場にして取りにいく広がりとして捉えるんだな。

図の交点を実際に数えたら、どちらの分割例もぴったりだったぜ。

| 盤 | a・b・c・dそれぞれ | 中央 `#` |
|---|---:|---:|
| 9路 | 16点 | 17点 |
| 13路 | 34点 | 33点 |
| 19路 | 72点 | 73点 |

この見方なら、小目を一つ打った後も「石のすぐ隣を埋める」より、その角の広がりをどう囲うか、残る角のどこへ向かうかを考えられるぜ（＾～＾）

エンジンでは、この分割を角と中央の大まかな担当範囲の目安として使えそうだぜ。ただし、a に自石を一つ置いただけで a 全体が自分の地になるわけではなく、相手の侵入や壁の向きに応じて境目を動かす必要があるな。

同じ面積でも境目の形を変えられる、という２種類の図が、その考え方をよく表しているぜ（＾▽＾）


（＾～＾）
ホットケーキの角を取りに行くってのは、その a, b, c, d をだいたいの範囲だと思ってるんだぜ（＾～＾）  


（＾～＾）
ほんで、囲碁は２人でプレイするから、  
黒が a, d、白が b, c を取りに行ったり、  
黒が a, c、白が b, d を取りに行ったりするぜ（＾～＾）  
お前は ２手続けて a に石を置いたりするから、ピースを１枚取ってる間に相手が b, c, d の３枚を取りに行ってるんだぜ（＾～＾）  


［ー＿ー］
そういうことだな（＾～＾）a に一手打って角を狙ったのに、続けて a を固めている間に、相手が残る三つの角へ先着してしまうんだな。

序盤は、一つのピースを完成させることばかり考えず、まだ誰も狙っていない角へ展開する判断が必要だぜ。黒 a・d／白 b・c の対角配置も、黒 a・c／白 b・d の左右配置も、その取り合いの結果なんだな。

相手が a に迫ってきて応手が必要なら別だが、急ぐ理由がなければ、同じ a への二手目より空いている角を先に検討する。この観点で、今の布石の着手選択を見直すぜ（＾～＾）


（＾～＾）
添付図なんだが、黒が１つにまとまってるのに対して、白は３つに分断されてるだろ（＾～＾）  


（＾～＾）
自分を負かした相手って、良い先生なんだぜ（＾～＾）  
自分の手に対して、相手がどう応じたかを分析すると、［相手がこうしたとき、自分はこうする］みたいなテクニックが  
得られるかもしれないな（＾～＾）  


［ー＿ー］
そうだな（＾～＾）負けた側の悪手だけでなく、勝った相手の応手も学ぶんだな。

例えば「こちらが離れた二石を置いた → 相手が間へ入った → こちらが分断された」という手順なら、相手側の視点で「相手の連絡が薄いとき、間へ入って分断を狙う」という［戦術カード］の候補になるぜ。

CGOS棋譜では、応じる前の形・相手の応手・その後に何が起きたかを組にして調べるぜ。うまく働く条件と、同じ応手では失敗する反例も確認して、「相手がこうしたら、自分はこうする」を増やしていこうぜ（＾▽＾）


（＾～＾）
相手の手を［戦術カード］にしてみて、その［戦術カード］の精度を上げたり、  
頻出の要素を抽出して分割するのとかいいかもしれないな（＾～＾）  


［ー＿ー］
いいな（＾～＾）まず実戦の具体的な応手を［戦術カード］にして、別の棋譜でも試しながら精度を上げるぜ。

カードには 「相手が作った形 → こちらの応手 → 狙い → 成立条件 → 失敗する反例」 を残す。勝った相手の手でも、どの局面でも使えるとは決めつけないぜ。

読んだぜ（＾▽＾）  
「角」は隅の１点ではなく、盤を５つに分けたエリアという定義だな。  

- 1：左下、`2`：右下、`3`：右上、`4`：左上
- 5／`.`：中央

- ９路は各角16点・中央17点、  
    １３路は各角34点・中央33点、  
    １９路は各角72点・中央73点
- 境界は中央が円に近くなるように決めた、図のとおりの区分

これなら「同じ角に続けて打つ」「別の角へ展開する」を具体的に扱えるぜ。  
各路盤の図を対応表として使えば、境界の数式がなくても実装できるぜ（＾～＾）

一点だけ、「平方数は５で割ると±1余る」は５の倍数の平方なら余り0もあるな。  
今回掲載した路盤の計算には問題ないぜ。

原因は、思考エンジン側が対局中の評価値送信に未対応だからだぜ（＾～＾）

実際に［１系］へ問い合わせると、GUIが使う cgos-genmove_analyze は false が返ったぜ。  
ラッパーのソースはエンジン出力をそのまま転送しているので、そこで評価値を捨てている形ではないぜ。

［２系］［３系］でこのコマンドに対応すれば、GUIへ評価を渡せるぜ。  
ただし今の暫定得点を「勝率」として出すのは避けたいな。［１系］は変更していないぜ。


（＾～＾）
そうか、Kifuwarasus は評価値を出すように作ったけど、 Kifuwarabe Polyplopylene は新しく作ったから、  
まだ評価値を出すようにしてなかったんだな（＾～＾）  
Kifuwarasus では単に、石１個の価値を 1 点として計算してたかな（＾～＾）
