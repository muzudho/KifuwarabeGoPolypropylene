# 思考エンジンの３系統とラッパー

配布ルートは `D:\Projects\KifuwarabeGoPolypropylene`。
外側の実行入口は `KifuwarabeGo2026.Tools.GtpEngineSwitch.exe`。
各対局でラッパーを起動し、開始時に同じフォルダーの `engine-switch.json` を読む。
ラッパーを起動し直さず同じプロセスで次局を始める環境では、その間に設定を変えても反映されない。

`1系`、`2系`、`3系` の各フォルダーには、次の４ファイルを一式で配置する。

- KifuwarabeGoPolypropylene.ThinkEngine.exe
- KifuwarabeGoPolypropylene.ThinkEngine.dll
- KifuwarabeGoPolypropylene.ThinkEngine.deps.json
- KifuwarabeGoPolypropylene.ThinkEngine.runtimeconfig.json

2026-11-25に2系・3系を現行1系の0.3.1から初期化した。研究中の最新版の配布ではない。
３系統それぞれでラッパー経由のprotocol_version/name/version/quit応答と正常終了を確認した。
現在の選択は1系。動いている対局のエンジンは設定変更で入れ替わらない。

## 次局で使う系統

`engine-switch.json` の `engines` 配列を保ったまま `primary` を1、2、3のいずれかにする。
例えば `"primary": 2` なら、次回ラッパー起動時に2系を使う。
GUI/CGOS側には個別のThinkEngine.exeではなく外側のGtpEngineSwitch.exeを登録する。

## 指定した系統だけ更新する

Releaseビルドを作成した後、配布先のPowerShellで実行する。

```powershell
.\Copy-Release.ps1 -Slot 2 -WhatIf
.\Copy-Release.ps1 -Slot 2
```

コピー元の既定値は、このPCのリポジトリーのThinkEngine\bin\Release\net10.0。
別のビルドを配布するときは `-SourceDirectory`、別PCの配布先には `-DestinationRoot` を指定できる。
系統指定は必須。４ファイルの存在を先に確認し、選んだフォルダーだけへコピーする。
primaryは変更しない。使用中の系統を上書きせず、使用していない系統へ配布してからprimaryを切り替える。
このスクリプトの一括コピーはトランザクションではなく、コピー途中の失敗時には４ファイルの整合性を再確認する。

研究の定期実行では配布先を自動更新しない。
ルートに残る旧ThinkEngine４ファイルは互換用に保持し、ラッパーの３系統設定では参照しない。
