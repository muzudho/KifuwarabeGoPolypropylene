# KifuwarabeGoPolypropylene

コンピューター囲碁の思考エンジン専用リポジトリー。GUI・ロビー・大会通信などは KifuwarabeGo2026 側を利用する方針です。

現在は C# / .NET 10 の接続確認用試作です。標準入力で GTP 2 のコマンドを受け取り、標準出力で応答します。KifuwarabeGo2026 v4.0.9 でのプレイヤー選択・着手は利用者が動作確認済みです。

## 起動

```powershell
dotnet run --project .\KifuwarabeGoPolypropylene.ThinkEngine
```

起動後、例えば次を1行ずつ入力します。

```text
protocol_version
boardsize 9
komi 6.5
play b D4
genmove w
showboard
quit
```

`genmove w` は `= A1` と空行を返し、白石を実際に置きます。応答の `=` は成功、`?` はエラーです。コマンド番号と `#` コメントも扱えます。通常運転中の標準出力は GTP 応答専用です。

## 動作テスト

外部テストパッケージを追加せず、次のコマンドで石の取り・自殺手・単純コウ・パス・座標・GTP 応答を検査します。失敗時は終了コードが非ゼロになります。

```powershell
dotnet run --project .\KifuwarabeGoPolypropylene.ThinkEngine -- --self-test
```

## 試作の範囲

- 2～19 路盤。黒・白の指定、パス、石の取り、自殺手禁止、単純コウ。
- 着手候補を A1 から順に仮想実行し、自動検出した失敗を戦訓として回避します。採用する候補がなければパスします。
- 中国式の面積計算（盤上の石＋自分だけが境界の空点）と白へのコミに対応します。コミは得点に反映しますが着手選択にはまだ使いません。
- 連続2パスを終局の目安とし、GTP `final_score` で面積得点を返します。死石の自動判定・合意除去、超コウ、時間管理、投了判断、置き石専用コマンド、undo、gRPC は未実装です。中国ルール全条項の完全実装ではありません。争いのある石は打ち続けて解消する前提です。
- 対応コマンドは `list_commands` で確認できます。大会用としての完成品ではありません。

ソースは既存の ThinkEngine フォルダーに置いています。Board.cs は盤面と合法手判定、GtpEngine.cs は文字列の接続口、Program.cs は起動、SelfTest.cs は検証です。

## KifuwarabeGo2026 v4.0.9 のエントリー登録

EXE のコピーとは別に、GTP エンジン → computer プレイヤー → 接続先情報の登録が必要です。2026-11-23 のローカル環境では、エンジン登録だけ存在し、対応するプレイヤーがありませんでした。

ロビーを終了してから `scripts/Register-LocalEntry.ps1` を実行すると、既存の `Kifuwarabe Go Polypropylene` エンジン登録を利用し、欠けているプレイヤーと空の接続先情報を追加します。起動パスも配置先の絶対パスに更新します。変更前の3つの JSON は同じ場所に日時付き `.bak` として保存します。実行後はロビーを再起動してください。

```powershell
.\scripts\Register-LocalEntry.ps1
```

このスクリプトの既定値は今回のローカル環境用です。別環境では `-SettingsRoot` と `-EngineDirectory` で指定してください。CGOS のログイン情報は空のため、大会接続には別途設定が必要です。エントリーの参照整合性と配置した EXE の GTP 応答は検証済みですが、GUI での表示・対局は未確認です。


## 戦訓と自動化サイクル（0.2.0）

最終対象は9路盤・19路盤、中国式の面積計算です。3路・5路は研究・回帰テスト用に使います。ルールの参考は中国囲棋協会の https://wqwh.weiqi.org.cn/rules/ 。得点は石と囲った空点を数え、中立点は両者に加えず、白へ指定コミを加えます。取った石を別途加算しません。残った石をすべて生き石として扱うため、死石が残る局面の値は推定です。複雑なコウの裁定や死活合意はまだ対応していません。

FolderVerse の `docs/dev/site-defense.md`、`FolderVerse/BattleLessons.cs`、`BattleLessons.Pursuit.cs` を参考に、失敗の観測と行動修正を分けています。FolderVerse の「目撃・帰還・研究」の演出は移植していません。

エンジン内では人の目視を待たず、候補手の仮想実行から次の失敗を自動検出します。

- `repeat-position`: 対局開始から記録した盤面へ戻る候補を回避する。パスは対象外。これは着手選択の方針で、外から受け取る着手の合法性判定は単純コウのままです。
- `fill-eye`: 上下左右が味方、斜めの敵石が内側なら1個以下・辺角なら0個の眼形を埋める候補を回避する。死活の完全証明ではなく局所的な判定です。
- `immediate-capture`: 取りを伴わない候補を仮に打ち、相手の合法な一手で置いた石が取られることを確認して回避する。捨て石の価値を読む機能はまだありません。

初期状態では取得0件です。失敗を初めて観測した時点からその候補を避け、同じ盤面・直前盤面・色・候補の経験を再利用します。`kfw-lessons` は取得した種類と観測数・回避数をJSONで返します。報告は起動中の複数対局を通して保持し、局面履歴と経験キャッシュは `clear_board` / `boardsize` でリセットします。プロセス終了後の学習保存はありません。

既知の3種類の検出と経験再利用がエンジン内の自動化です。未知の失敗から新しいC#の戦訓を作る部分は、定期タスクの Codex が対局証拠を読み、再現テストと実装を追加する開発サイクルとして行います。エンジン単体が未知のルールを発明する機能ではありません。

### 定期検証の実行

PowerShell 7 から次を実行します。

```powershell
.\scripts\Invoke-LessonCycle.ps1 -TimeoutSeconds 300 -Games 32 -Seed 1
```

NAS に隔離した Release ビルド → 自己テスト → 対局・証拠保存を順に実行します。合計5分が上限で、超過した子プロセスはツリーごと停止します。終了コードは成功0、失敗1、タイムアウト2。同時実行は排他ロックで防ぎます。NAS が使えなければローカルに大きな代替出力を作らず終了します。ビルドしたものをインストール先へ自動コピーはしません。

既定の保存先は `Z:\muzudho-with-ai-agent\KifuwarabeGoPolypropylene\tmp\delete-after-YYYY-MM-DD\lesson-cycle\実行日時-seed番号`（期限は実行日＋7日）です。日付は削除候補の目安で、スクリプトが自動削除することはありません。

- `games.jsonl`: 手順（点番号は左下A1=0から行順、nullはパス）、種、盤サイズ、対戦方式、終局・手数上限・タイムアウトの区別、戦訓統計と失敗例の盤面。
- `summary.json`: サイズ別集計。9路・19路を優先し、自己対局・ランダム相手と異なる序盤を試す。得点計算の検証には固定局面を使い、ランダム相手との結果を棋力向上の証明にはしない。
- `source-hashes.json`: 実行したソースのSHA256。`build/`、標準出力・標準エラーログ、`run-status.json` も同じ場所に保存する。

対局は各局 `盤面点数×8＋100手` でも打ち切ります。手数上限やタイムアウトを「終局」「非収束の証明」「強さの改善」に読み替えません。新戦訓は再現局面と適用しない反例をテストしてから採用します。

2026-11-23 の検証: Release ビルド警告0・エラー0、675チェック合格。固定自己対局は3路15手・5路26手・9路108手・19路467手で連続2パス。NAS上の8対局（SEED20261123）は全局連続2パス、盤面再出現0。9路・19路は各2局なので、一般的な収束や棋力の保証ではありません。上限1秒の試験ではビルドのプロセスツリーを停止し、終了コード2と記録を確認しました。

定期タスク「囲碁エンジンの戦訓を自動研究」をこのチャットに登録済み（2026-11-23）。1時間ごとに実行し、検証プロセスは合計300秒で停止します。Codexによる調査・実装は1回15分を目安に区切る指示であり、エージェント全体の強制停止ではありません。新しい失敗が再現できた場合だけ戦訓と回帰テストを追加し、根拠がなければ無理に追加しません。ローカル定期タスクのためPCとアプリを起動しておく必要があります。既存のアプリ配置先は自動更新しないので、採用した変更を使う際は通常のReleaseビルドとCopy-Release.ps1で更新してください。
